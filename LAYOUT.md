# Layout

| Path | Role |
|---|---|
| `AGENTS.md`, `CLAUDE.md` | Guidance for coding agents. `CLAUDE.md` only imports `AGENTS.md` for Claude Code, so the guidance stays in one file. |
| `SECURITY.md` | How to report a vulnerability, and the trust model: what pins, checks and sandboxes do and don't cover. Keep it in sync with the workflows, `lib/` and the modules. |
| `flake.nix` | Discovers `pkgs/*/package.nix` and the module files; builds all packages in one `makeScope` so they can depend on each other by argument name; filters `packages.<system>` with `lib.meta.availableOn`, except for the packages in `fixedPlatforms` (they fetch Hermes' flake when evaluated). `checks` builds every package but the `rolling` ones (`ghostty-tip`, whose pin expires with each upstream build) and adds `formatting` (`nixfmt --check`) and, on Linux, `lint` (shellcheck over the shell scripts, actionlint over the workflows) and `nixos-modules` (a NixOS system with every NixOS module enabled, evaluated). |
| `overlays/default.nix` | `pkgs.xr3t.<name>`, built against the consumer's nixpkgs. |
| `pkgs/<name>/package.nix` | The derivation. Read `version`/hashes from `hashes.json` for prebuilt binaries. |
| `pkgs/<name>/hashes.json` | `{ "version": ..., "hashes": { "<key>": "sha256-..." } }`, written by `update.sh`. Keys are whatever the package looks up (usually the system). Exception: `hermes-agent` pins an upstream flake as `{ version, rev, narHash }`. |
| `pkgs/<name>/update.sh` | Optional. Bumps `hashes.json` to the latest upstream; no-op when current. Run by `.github/workflows/update.yml`. Sources `lib/update.sh`. |
| `lib/hardening.nix` | The systemd sandboxing the opt-in `hardening.enable` options share (`serviceConfig`); each module adds what its service can live without. Modules otherwise run services as upstream's installer does. |
| `lib/update-all.sh` | What `update.yml` runs, once per `UPDATE_SYSTEM`: every `update.sh` of that system's packages (`x86_64-linux`: all that build there; `aarch64-darwin`: those that build only on macOS), each update built (`nix flake check --keep-going`) before it lands, and on Linux the weekly `nixpkgs` bump. After proposing an update it deletes the `pull_request` runs that GitHub holds for approval on a pull request this token opened or pushed (they would fail once the dispatched `check.yml` merges it). |
| `lib/changed-checks.sh` | Prints the checks of a system whose derivation differs from those at a git revision; `check.yml` builds only those on macOS. Evaluation only, so it runs on Linux. |
| `lib/macos-check-plan.sh` | Run by `check.yml`'s `plan` job, on Linux. Selects macOS checks against a successful ancestor Check of the PR base branch or `main`, including merged PRs; falls back to all checks without a baseline or when check machinery changes. |
| `lib/macos-cache-key.sh` | Hashes macOS package derivations (including rolling packages) for the store cache `update.yml`'s macOS job keeps between runs; Linux-only changes do not replace it. |
| `lib/macos-app-release.py` | Selects the newest stable WhatsApp or native Telegram version/build from the official Sparkle feed; validates the download URL against each vendor's release endpoint. |
| `lib/check-app.py` | Install check for a macOS app bundle: its executable exists, and its version is the pinned one; optional build-number and native Mach-O architecture checks. |
| `lib/codesign-check.py`, `lib/apple-root-ca.pem` | Checks Apple code signatures without macOS (`rcodesign`, `openssl`): a Mach-O file's every slice intact and signed by a Developer ID Application certificate of the given team chaining to Apple's root CA (pinned by fingerprint in the PEM); for an `.app` or `.framework`, also its whole seal (`Info.plist`, `CodeResources`, every listed file, nested code by cdhash, nothing unsealed). A package that exposes it as `passthru.codesign` also gets `checks.<linux>.<name>-codesign`, macOS-only packages included (`claude-code`, `claude-desktop`, `kiri`). |
| `lib/update.sh` | Helpers for `update.sh`: `check_version` (rejects unexpected upstream versions), `gh_latest`, `skip_if_current`, `prefetch` (checks a download against upstream's sha256 when given one, and a GitHub release asset against GitHub's digest), `write_hashes` (with `sums` set, against upstream's checksum list or per-file `.sha256`). |
| `pkgs/<name>/module.nix` | Optional. `self: { config, ... }: { ... }`; exported as both `darwinModules.<name>` and `nixosModules.<name>`. Default package is `self.packages.${system}.<name>`. |
| `pkgs/<name>/nixos-module.nix`, `darwin-module.nix` | Same shape as `module.nix`, exported only to `nixosModules` or `darwinModules`. |
| `pkgs/<name>/home-module.nix` | Same shape, exported as `homeManagerModules.<name>`. |
| `pkgs/<name>/*.asc` | Optional. An upstream release signing key that `update.sh` checks signatures against (`claude-code`), pinned by fingerprint in the script. |
| `pkgs/<name>/*.mobileconfig` | Optional. A macOS configuration profile the package ships for the user to approve, for a setting the app reads only from managed preferences (`claude-desktop`). |
| `pkgs/README.md` | The package table: each package, what it brings and the systems it runs on, in alphabetical order. The top-level README links to it. |
| `pkgs/<name>/README.md` | Optional. The package's usage, options and maintenance notes. |
| `.github/workflows/check.yml` | `nix flake check --keep-going` on Linux x86_64 and aarch64, each runner for its own system only; a `plan` job on Linux evaluates the macOS checks and lists those that differ from a successful ancestor of the PR base branch or `main` (including merged PRs), and a macOS runner starts only when there are any, to build just those, with no store kept between runs; cancels older Check runs for the same branch, with PR events separate so they cannot cancel update auto-merges; read-only token, not kept in the checkout; only on `main` the Linux jobs push `hermes-agent` (x86_64) and `llama` (only) to ret.cachix.org; when `update.yml` starts it on `update/<name>` and all systems pass, its `merge` job deletes that commit's `pull_request` runs still waiting for approval, merges that pull request and starts `check.yml` on `main`. |
| `.github/workflows/update.yml` | Twice daily (03:17, 15:17 UTC), one run at a time: runs `lib/update-all.sh` on Linux, then on macOS for the macOS-only packages, so each update is built on a system it runs on; checks the flake, commits `Update <name> to vX.Y.Z` to `main`, or for the packages in `REVIEW` opens a pull request from `update/<name>` and starts `check.yml` on it, which merges it once green; the macOS job keeps its Nix store between runs with cache-nix-action (it builds every macOS check for each update); on Monday's first run (or when asked for) updates the `nixpkgs` input the same way, always as a pull request (`update/nixpkgs`); then pushes `hermes-agent` and `llama` to ret.cachix.org. |
| `.github/dependabot.yml` | Weekly bumps of the actions, which workflows pin by commit SHA. |
